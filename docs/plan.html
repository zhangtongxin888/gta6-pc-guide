2. 信息核查：真、待证、假

“真”= 官方或 3 家以上独立媒体一致；“待证”= 单一来源、匿名信源或当事人自述；“假”= 已被证伪或与官方信息冲突。

3. 现站问题

首屏答非所问

首屏整屏是 Neon Bay 小游戏，“PC 版没出”这句答案在第二屏。搜索者 3 秒内看不到答案就会走。

内容过期

全站写着 “Last reviewed: July 2026”，主机版还被当成“即将发售”。没有 Q1 2027 报道、DF 实测、泄露和移植的任何内容。

页面太少

只有 3 页（sitemap 也只有 3 个 URL），P1 里的“移植追踪”“EXE 泄露”两个新意图没有落地页。

纯前端渲染

HTML 里只有 <div id="root">，正文靠 JS 渲染。新闻类词拼时效，建议改成预渲染/静态输出，让爬虫第一次就拿到正文。

5. 样例里做了什么

  • 保留品牌：沿用现站的深紫底、粉/青双色、Archivo Black 标题字，只把首屏从游戏换成答案。
  • 首屏 = 答案：大标题 “Is GTA 6 on PC? Not yet.” + 右侧三灯状态台，每盏灯链到对应页面。
  • 发售日用两条线并列：GamesBeat 的 Q1 2027 和 Rockstar 历史推算画在同一时间轴上，不替用户选边。
  • 移植追踪用统一的 7 阶段梯子：把“能启动了”这类标题党新闻放到同一把尺子上比，项目表支持搜索和按阶段筛选。
  • 每页都有“下一步”和侧栏，正文末尾有来源一行小字，全站中立不站队。

6. 红线（建议写进站规）

  • 不放、不链接任何泄露文件、EXE、种子、网盘，以及需要泄露文件才能用的移植仓库。样例里只写项目名，不放 GitHub 链接。
  • 不用“下载”“破解”当标题或锚文本，避免被当成盗版站；Take-Two 对 GTA 相关内容的 DMCA 一向很快。
  • 待证的信息一律标注“报道称 / 自述 / 社区预测”，不写成事实。

7. 上线后要维护的东西

  • 移植追踪表：一天至少更新一次。数据变化很快（24 日一天内各项目的状态改了好几轮），建议把项目表做成 JSON 数据，构建时生成。
  • 状态台三盏灯：一旦 Rockstar 公布 PC 版、或有民间版进到“可操作角色”，当天改灯和首屏标题。
  • 风险：民间移植随时可能被集中下架，这一页的流量是阶段性的；官方 PC 版公布后，流量会回到 release date / specs / steam 这几页，所以旧页也要一起改好。
